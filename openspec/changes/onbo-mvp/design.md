# Design

## Context
См. proposal.md. Одобрен план MVP для трёх участников на 1–2 дня. Существующего приложения нет. GigaChat API — физлицо; ключ/модель вводятся локально, доступность API ещё не проверена.

## Goals / Non-Goals
**Goals:** три связанных сценария, серверные гарантии прав/подтверждения/повтора, воспроизводимость и проверки.
**Non-Goals:** публичный деплой, кабинет наставника, редактор планов, векторная БД, потоковый чат.

## Decisions
- Go API и React на одном origin; контракт docs/api.md, общие типы internal/core/types.go.
- PostgreSQL хранит состояние, Redis — сессии и лимиты; SQL-поиск с фильтрацией команды до передачи модели.
- Два синтетических профиля, четыре шага и один ресурс. Ручные шаги отмечает пользователь, доступ завершается только granted.
- Пять инструментов модели; подтверждение отправки — отдельная операция интерфейса. Черновики неизменяемые, заявка сохраняется до HTTP-вызова. Имитация хранит уникальный ключ и позволяет восстановить результат.
- Родной API GigaChat: OAuth PERS, конфигурируемые endpoint/model/CA, сохранение function_state, до пяти итераций. Детерминированная подмена явно маркируется режимом demo.
- Docker Compose app/mock/PostgreSQL/Redis; секреты только из окружения, без отключения TLS.

## Risks / Trade-offs
- Непроверенный реальный ключ → отдельный smoke/eval сценарий, отсутствие ключа не скрывается подменой.
- Короткий срок → компактный UI и тесты вместе с реализацией.
- Docker Engine пока не запущен → проверить доступность перед сборкой.

## Migration Plan
Первый запуск создаёт схему и идемпотентно добавляет тестовые данные. Данные в именованных томах. Остановка без удаления томов сохраняет прогресс.
