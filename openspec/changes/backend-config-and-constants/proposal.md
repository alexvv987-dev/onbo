# Proposal

## Why

Настройки backend распределены между точками запуска и адаптером GigaChat, а статусы, строки протокола и числовые ограничения повторяются в обработчиках, SQL и агенте. Пользователь запросил YAML-конфигурацию с переопределением через окружение и именованные константы, чтобы настройки и правила было проще проверять и обсуждать.

## What Changes

- Добавить `internal/config/config.go` в формате cleanenv с yaml/env/env-default/env-required тегами, time.Duration, MustLoad и testable Load, defaults из тегов, строгим разбором YAML, наложением окружения и валидацией до подключения к зависимостям.
- Добавить `configs/onbo.yaml` и `configs/mock.yaml` без секретов; путь переопределяется через `CONFIG_FILE` отдельно для каждого процесса.
- Передавать готовые настройки конструкторам, убрать распределённые чтения окружения из прикладных Go-модулей. Сохранить запуск из окружения без файла.
- Вынести доменные и протокольные строки, сообщения, SQL и фиксированные числовые значения в осмысленные `const`-блоки после импортов в файлах использования; HTTP-коды заменить стандартными `http.Status*`.
- Переименовать переменные, параметры, receiver-параметры, внутренние функции и методы Go по их назначению; исключить однобуквенные имена, включая циклы, тесты и generic-параметры. Сохранить требуемые Go/библиотеками имена и внешние строковые контракты.
- Сохранить значения по умолчанию, JSON-контракты, текущие переходы статусов, права и идемпотентность. Изменение обработки некорректной конфигурации намеренное: fail-fast вместо молчаливого принятия.
- Адаптировать будущие проверки, Compose/Docker, `.env.example`, README и локальный roadmap к новому способу настройки.

## Capabilities

### New Capabilities

- `service-configuration`: предсказуемая загрузка конфигурации Go-процессов из defaults, YAML и окружения с валидацией и безопасной обработкой секретов.

### Modified Capabilities

Нет. Действующие требования MVP не меняются; перенос констант и переименование внутренних символов — рефакторинг. В основной `openspec/specs` сейчас нет сохранённых capabilities, требования MVP находятся в отдельном изменении `onbo-mvp` и учитываются как контекст совместимости.

## Impact

Затрагиваются `cmd/onbo`, `cmd/mock`, `cmd/eval`, `internal/backend`, `internal/agent`, `internal/mock`, `internal/core`, новые `internal/config` и `configs`, связанные тесты и документация запуска. Закреплены cleanenv v1.5.0 и go.yaml.in/yaml/v3 v3.0.6 для строгой проверки YAML перед загрузкой. Frontend и бизнес-функциональность не расширяются; публичный деплой и работающий экземпляр приложения в рамках подготовки плана не затрагиваются.
