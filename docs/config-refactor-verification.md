# Проверка конфигурации и рефакторинга Go

Дата: 14 ноября 2026 года, Europe/Moscow. Это отдельный отчёт после исходного MVP; результаты в `verification.md`, исходной презентации и прежнем архиве относятся к предыдущему состоянию.

## Что изменилось

- `internal/config/config.go`: типы Config/Mock/Agent, вложенные настройки, теги `yaml`, `env`, `env-default`, `env-required`, обычный `time.Duration`, функции MustLoad/MustLoadMock. Для управляемого запуска предусмотрены Load/LoadMockFile с возвратом ошибки.
- `cleanenv` v1.5.0 выполняет ParseYAML проверенного снимка и ReadEnv. `go.yaml.in/yaml/v3` v3.0.6 обеспечивает предварительную проверку схемы и типов. Файл не открывается повторно; расширение не выбирает другой парсер.
- Defaults читаются из тегов без окружения. Прежние настройки сохранены; у app и mock собственные HTTP-defaults. Явные нулевые YAML-значения не подменяются повторными defaults cleanenv.
- YAML-файлы поставляются в образе, CONFIG_FILE задаётся отдельно для app/mock. Секретные поля разрешены только из окружения.
- Конфигурация выделена в config.go адаптеров и точек запуска. Константы размещены после импортов в файлах использования, общие доменные значения — рядом с типами core. Ошибки backend/agent находятся в errors.go.
- Однобуквенные объявления исключены; методы Tools/Sessions/Store переименованы по действию и предметной области. Внешние JSON/HTTP/LLM-значения сохранены.

## Проверка отдельного runtime-образа

Девять проверок HTTP-сценария прошли в app/mock контейнерах нового образа с явным LLM_MODE=demo:

1. Запуск с YAML и корректное обозначение demo-режима.
2. SESSION_TTL=30m переопределяет YAML и даёт cookie Max-Age=1800.
3. Ответ по инструкции содержит доступные источники после переименования инструментов.
4. Отсутствует отправка при confirmed=false; повтор подтверждения возвращает одну заявку.
5. Результат granted завершает шаг доступа.
6. Заявка и прогресс сохраняются после перезапуска отдельного app.
7. Второй профиль не читает чужие заявки и не подтверждает чужой черновик.
8. Явный отсутствующий CONFIG_FILE останавливает запуск до подключения зависимостей.
9. В environment runtime-образа нет ключа модели и credentials приложения.

Первый smoke остановился после перезапуска: Docker изменил автоматически выбранный host port. После повторного определения порта сценарий прошёл. У отдельного mock задан healthcheck на 8081, как и в Compose; image-default относится к app на 8080. Это особенности тестового запуска, не изменение бизнес-логики.

Проверка HTTP не заменяет браузерную оценку удобства. Frontend в этом изменении не редактировался.

## Независимое ревью и ограничения

Независимое ревью loader и остальных Go-модулей завершилось PASS после исправления замечаний: строгие scalar-типы YAML, нормализация режима, hostname/port, безопасные field paths, дробное окно quota, единый снимок и однозначные целочисленные env. Целочисленные env используют каноническую десятичную запись без ведущих нулей и `+`; это явно описано в README.

Настоящий GigaChat в рамках этого изменения не вызывался. Его протокол проверялся локальными HTTP-подменами; предыдущий live-отчёт MVP не выдаётся за новый прогон. Рабочий `.env`, ключ, CA и работающее demo не изменялись и не перезапускались. Публикации, commit и push не выполнялись.
