# MCP и метрики

## MCP-слой

Прототип публикует локальный каталог MCP-действий через `GET /api/mcp/tools`.
Каталог содержит пять действий агента: план адаптации, поиск инструкции, каталог
доступов, черновик заявки и статус заявки. Сам каталог не выдаёт права и не
принимает идентификатор пользователя от модели: авторизация остаётся в Go API,
а текущий профиль берётся из cookie-сессии.

Это прототипная интеграция: реальные внутренние MCP-сервера Авито не подключаются,
а корпоративный сервис заявок заменён HTTP-имитацией.

## События

UI отправляет обезличенные события на `POST /api/events`. Сервер проверяет имя,
размер и число свойств, затем сохраняет событие в PostgreSQL. Тексты вопросов,
ответов и причины заявок в событие не попадают.

События: `plan_opened`, `task_completed`, `question_asked`, `source_shown`,
`draft_created`, `request_confirmed`, `request_result`, `request_refreshed`.

Для продуктовой проверки считаются конверсия по шагам плана, доля вопросов с
источником, время от черновика до результата и доля заявок со статусом `granted`.
Эксперимент с пользователями описан в `docs/product-validation.md`.
