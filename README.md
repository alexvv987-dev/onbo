# Онбо

ИИ-помощник для первых дней стажёра: персональный план, ответы по инструкциям с источниками и подтверждаемая заявка на доступ. Проект для кейса «AI-buddy», Hack&Change 2026.

Все профили, инструкции и корпоративные сервисы синтетические. Это не регламенты Авито. Реальные доступы во внешние системы не выдаются.

## Запуск

Нужны Docker Engine и Compose v2. Для тестов дополнительно: Go 1.26.5+, Node.js 24 и npm. Библиотеки закреплены в go.mod/go.sum и package-lock.json.

```powershell
Copy-Item .env.example .env
docker compose up --build -d --wait
```

Откройте [http://localhost:8080](http://localhost:8080). По умолчанию `LLM_MODE=demo`: детерминированная подмена, без ключа и внешнего API. Интерфейс явно показывает режим.

Если Docker Desktop на Windows с кириллицей в пути сообщает `x-docker-expose-session-sharedkey ... non-printable ASCII`, используйте проверенный обход:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -Mode demo
```

Скрипт устанавливает `COMPOSE_BAKE=false`, `DOCKER_BUILDKIT=0` только для своего процесса. На других окружениях обычной команды Compose достаточно.

Остановка: `docker compose stop`. Перезапуск приложения: `docker compose restart app`. Именованные тома сохраняют данные. `docker compose down -v` удаляет данные и для обычной остановки не нужен.

## Конфигурация Go-сервисов

Типы настроек находятся в `internal/config/config.go`: `Config`, `Mock`, `Agent`
и вложенные структуры с тегами `yaml`, `env`, `env-default`, `env-required`.
Значения по умолчанию определяются тегами `env-default`; `Default*` читает эти
теги без обращения к окружению. Для HTTP app и mock предусмотрены собственные
типы с правильными портами и сроками ожидания. Загрузка выполняется через
закреплённый `cleanenv`: проверенный снимок YAML декодируется через `ParseYAML`,
затем применяется `ReadEnv`, без повторного открытия файла и выбора другого
парсера по расширению. `MustLoad(path)` / `MustLoadMock(path)` завершают процесс
при ошибке; `Load(path)` / `LoadMockFile(path)` возвращают ошибку для тестов и
управляемого запуска. Настройки адаптеров выделены в их `config.go`.

Настройки загружаются из именованных defaults, затем `configs/onbo.yaml` или
`configs/mock.yaml`, затем переопределяются явно заданными переменными окружения.
`CONFIG_FILE` выбирает другой файл; относительные пути считаются от рабочего каталога.
Если стандартного файла нет, поддерживается запуск только из окружения. Ошибка
явного пути, неизвестные/повторные YAML-поля, несколько документов и некорректные
значения останавливают запуск до подключения к зависимостям. Файл ограничен 64 KiB.

Секреты `DATABASE_URL`, `REDIS_PASSWORD`, `MOCK_TOKEN`,
`GIGACHAT_AUTHORIZATION_KEY` допускаются только из окружения и не разрешены в YAML.
`.env` по-прежнему загружает Compose; Go сам этот файл не читает. Длительности
задаются с единицами (`500ms`, `30s`, `12h`); session TTL — целыми секундами.
Окно лимита поддерживает дробные секунды; Redis PEXPIRE округляет его вверх до
миллисекунды. Session TTL одновременно задаёт срок Redis-сессии и cookie MaxAge.
Явные `false` и пустая optional-строка переопределяют YAML; пустое обязательное
значение и некорректный bool/int/duration приводят к безопасной ошибке.
Целочисленные env задаются канонической десятичной записью (`20`, `32768`),
без ведущих нулей и `+`: это исключает восьмеричную интерпретацию в cleanenv.

| Секция YAML | Переопределения окружения |
|---|---|
| HTTP / lifecycle | `HTTP_ADDR`, `HTTP_READ_HEADER_TIMEOUT`, `HTTP_READ_TIMEOUT`, `HTTP_WRITE_TIMEOUT`, `HTTP_IDLE_TIMEOUT`, `INIT_TIMEOUT`, `SHUTDOWN_TIMEOUT` |
| Redis / sessions | `REDIS_ADDR`, `REDIS_DIAL_TIMEOUT`, `REDIS_READ_TIMEOUT`, `REDIS_WRITE_TIMEOUT`, `SESSION_TTL`, `CHAT_RATE_WINDOW`, `CHAT_RATE_LIMIT` |
| Mock client | `MOCK_URL`, `MOCK_TIMEOUT` |
| API / mock limits | `HEALTH_TIMEOUT`, `MAX_REQUEST_BYTES`; `CHAT_TIMEOUT` — только app |
| LLM | прежние `LLM_MODE`, `GIGACHAT_MODEL`, `GIGACHAT_API_URL`, `GIGACHAT_OAUTH_URL`, `GIGACHAT_SCOPE`, `GIGACHAT_CA_FILE`, новые `GIGACHAT_REQUEST_TIMEOUT`, `GIGACHAT_REPLY_TIMEOUT` |
| App | `DEMO_MODE`, `STATIC_DIR` |

Прямой Go-запуск по умолчанию требует GigaChat; Compose сохраняет явный demo-режим.
Параметры из `environment` Compose имеют приоритет над `env_file`, а оба источника
перекрывают YAML. Eval загружает только настройки модели и не требует БД/Redis.

Константы объявлены блоками непосредственно после импортов в файлах использования.
Общие доменные значения находятся рядом с типами в `internal/core/types.go`;
ошибки пакетов — в `errors.go`. `go run scripts/check-go-style.go` проверяет
объявления Go AST: отсутствие однобуквенных имён, const-блоки и их размещение.
JSON/YAML/env-теги, структурные JSON-ключи, простые проверки `0`, `1`, `""`,
а также независимые ожидания и синтетические данные тестов не заменяются
механически константами. HTTP-коды и методы используют стандартный `net/http`.

## Настоящий GigaChat

1. В локальном `.env` задайте `LLM_MODE=gigachat`, `GIGACHAT_AUTHORIZATION_KEY` и `GIGACHAT_MODEL`. Проверенный идентификатор в этой реализации — `GigaChat-2`; доступ определяется аккаунтом.
2. Скачайте официальный доверенный CA: `node scripts/setup-certificates.mjs`.
3. Укажите `GIGACHAT_CA_FILE=/app/certs/gigachat-ca.pem`. Compose монтирует certs только для чтения. Ключ и сертификаты не входят в образ и Git.
4. Запустите `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -Mode gigachat` или обычный Compose.

Используется прямой GigaChat API для физлица, scope `GIGACHAT_API_PERS`. Go получает и обновляет OAuth-токен, передаёт описания функций модели, проверяет и исполняет её вызовы. Лимит — пять вызовов инструментов. Сбой настоящей модели возвращает ошибку и не включает demo. TLS проверяет цепочку и имя сервера.

Настройки адресов есть в `.env.example`. Источники: [авторизация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api), [функции](https://developers.sber.ru/docs/ru/gigachat/guides/functions/generating-arguments-for-custom-functions), [сертификаты](https://developers.sber.ru/docs/ru/gigachat/certificates).

Проверка доступных моделей без вывода токена:

```powershell
$env:GIGACHAT_CA_FILE=(Resolve-Path certs/gigachat-ca.pem).Path
node --env-file=.env scripts/gigachat-models.mjs
```

## Три сценария

Демонстрационный вход имитирует корпоративную авторизацию. Паролей нет: выберите профиль. Вход доступен только при `DEMO_MODE=true`.

| Профиль | Команда | Проверка |
|---|---|---|
| Саша Иванова (`intern-platform`) | Платформа | Полный путь до доступа к учебному репозиторию |
| Миша Петров (`intern-analytics`) | Аналитика | Недоступность ресурса и заявок другой команды |

1. Отметьте знакомство с командой и ознакомление с инструкцией. Обновите страницу: прогресс сохранён.
2. Спросите «Как подготовиться к первой задаче? Найди инструкцию». Проверьте название и фрагмент источника. При отсутствии доступной инструкции помощник сообщает об этом.
3. Спросите «Подготовь заявку на доступ к учебному репозиторию для первой задачи». До подтверждения существует только неизменяемый черновик. После нажатия кнопки появятся номер сервиса и ожидание.
4. В блоке «Имитация сервиса» выберите выдачу или отказ. Только `granted` означает «Доступ выдан». Первую задачу стажёр отмечает самостоятельно после разблокировки.
5. Переключите профиль: чужая история и заявки не раскрываются.

Повтор подтверждения возвращает прежнюю заявку. `submitting` означает неизвестный исход внешнего вызова: обновление или повтор подтверждения восстанавливает результат по устойчивому ключу. Устаревший ответ не откатывает терминальный статус.

## Архитектура

```text
React + TypeScript
       |
       v
Go API ---- GigaChat (OAuth, функции)
  |  |
  |  +---- HTTP-имитация сервиса заявок
  v
PostgreSQL + Redis
```

PostgreSQL хранит прогресс, инструкции, черновики, операции, диалоги и долговечное состояние имитации. Поиск — полнотекстовый SQL с фильтром команды до передачи данных модели. Redis хранит сессии и лимиты чата.

Go обслуживает React на одном origin, проверяет идентичность, ACL, Origin и JSON. Модель имеет пять инструментов; отправка заявки — отдельная серверная операция после подтверждения. Имитация отделена HTTP-контрактом и требует межсервисный токен.

Контракты: [API](docs/api.md), [SDD](openspec/changes/onbo-mvp/), [проверки ИИ](docs/ai-evaluation.md).

## Автоматические проверки

```powershell
npm ci
npm --prefix web ci
npm run verify
```

Проверка запускает PostgreSQL/Redis, `go vet`, Go unit/integration tests, TypeScript, UI-тесты, frontend build, OpenSpec strict и Compose config. Тесты используют временные схемы и не стирают демонстрационные данные.

Отчёты: `reports/go.cover`, `reports/coverage.json`, `web/coverage/`. Общий порог — строго больше 80% строк всего прикладного кода, включая команды и имитацию. Go statement-блоки переводятся в уникальные инструментированные строки, затем объединяются со строками V8 с весом по количеству строк. Методика записана в JSON. Зависимости, сборки и тесты исключены.

Для отдельных Go integration tests задайте `ONBO_TEST_DATABASE_URL` и `ONBO_TEST_REDIS_ADDR`. Локальные порты Compose: PostgreSQL 55432, Redis 16379, app 8080, mock 8081, все привязаны к loopback.

Браузерная проверка и запись видео:

```powershell
npx playwright install chromium
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -Mode demo
npm run e2e
```

Проверяются интерфейс, подтверждение, повтор, права второго профиля, мобильная ширина и сохранность после перезапуска app. Запись создаётся локально в `output/video/onbo-demo.webm` и не включается в Git; порядок демонстрации описан в [сценарии](docs/demo-script.md).

Настоящая модель проверяется отдельно:

```powershell
docker compose exec -T -e LLM_MODE=gigachat app /app/eval
```

Live eval выводит JSON 13 случаев и использует только синтетические инструменты в памяти, без отправки заявок. Ожидаемый инструмент засчитывается только при выборе самой моделью. Успех набора не доказывает качество на произвольных запросах.

## Материалы и ограничения

- [Результаты проверок MVP](docs/verification.md). PDF-презентация в `output/pdf/` и записи в `output/video/` хранятся локально и исключены из Git.
- [Проверки конфигурации и Go-рефакторинга](docs/config-refactor-verification.md): отдельный актуальный отчёт, покрытие и ограничения.
- [Протокол пользы](docs/product-validation.md): время, успешность, обращения за помощью. Исследование ещё не проведено, экономия времени пока гипотеза.
- Реальных данных сотрудников и production-авторизации нет. Доступ выдаёт имитация. Кабинет наставника, редактор планов, потоковый чат и публичное размещение не входят в MVP.
- Реализация подготовлена с помощью Codex. План распределения работ не означает участие трёх конкретных людей. SDD и история изменения находятся в репозитории.

OpenSpec установлен локально: `npm run openspec -- <команда>`. Спецификации на русском, структурные заголовки OpenSpec сохранены.
